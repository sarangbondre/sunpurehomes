# 0002 — Arka: a small-model sales assistant on a RERA-registered site

Date: 2026-09-16
Status: Accepted — switched off 17 September 2026

**17 September 2026:** the client asked for the chat to be removed. It is
switched off, not deleted: `ARKA_ENABLED` (default off) hides the launcher on
every page and makes `/api/chat` and `/api/lead` answer 404, so nothing can
reach a model or the email provider. A WhatsApp button holds the corner
instead. Setting `ARKA_ENABLED=true` and redeploying brings Arka back as
described below.

## Context

The client asked for a chatbot that answers questions about the nine projects,
captures leads with a note of where they came from, and hands anything else to
the sales team by WhatsApp, phone or email. The mascot is **Arka** — Sanskrit
for a ray of the sun.

Three things make this riskier than a generic support bot:

1. **It speaks for a RERA-registered developer.** A wrong price, unit count or
   registration number is a misrepresentation, not a typo. BRIEF §15 names
   "confidently displaying wrong information" as the failure this rebuild
   exists to prevent.
2. **The content admits its own gaps.** All nine projects carry
   `contentWarnings` — disputed unit counts, unverified distances, a promoter
   entity not yet confirmed. There is no price field anywhere.
3. **It was the site's first server code.** Until this, every page was static:
   no route handlers, no secrets, no personal data.

The client asked for the cheapest option that works, and asked whether an
open-source model would do.

## Decision

**A small model, made safe by what it is given rather than by what it is told.**

- **Model: Llama 3.3 70B through Hugging Face Inference Providers, pinned to
  Novita** — switched from Claude Haiku 4.5 at the client's instruction on
  16 September 2026. Claude, or any other OpenAI-compatible host, is one
  variable away (`ARKA_PROVIDER`). Everything sits behind one adapter
  function (`src/lib/chatbot/provider.ts`); nothing outside it imports a
  vendor SDK.
- **Retrieval is deterministic.** Projects are chosen by name, then by recent
  conversation, then by the page being read — never by embeddings. Nine
  similar records are the case where semantic search returns the wrong
  project and the answer still looks right. No vector store, no chunking.
- **Unsafe facts are removed from the corpus, not guarded in the prompt.**
  `WITHHELD` in `src/lib/chatbot/corpus.ts` strips each disputed figure —
  including where a description spells it out in words — and fails the build
  if a redaction stops matching its content. The warnings themselves never
  enter a prompt.
- **The two highest-stakes rules are code.** `guards.ts` holds each sentence
  until it is checked: a price is never sent to the browser, and a phone
  number, email or link is removed. The widget, not the model, renders the
  contact buttons, from `site.ts`.
- **Leads come from a form, not from the model.** Provenance — the page they
  asked on, the external referrer and campaign tags captured on arrival — is
  taken from the request, never from anything the model said.
- **An eval set** (`evals/arka.json`, 26 cases) is the bar any model must
  clear before it serves visitors.

## Cost

Measured prompt size: ~900 tokens with no project in scope, ~1,400–1,500 with
one. About 200 tokens out per reply. Six turns a conversation, ₹90/$.

| Model | per conversation | 300 conversations/month |
|---|---|---|
| Llama 3.3 70B via Hugging Face → Novita (default) | ~₹0.14 | ~₹42 |
| Llama 3.1 8B via Hugging Face → DeepInfra | ~₹0.02 | ~₹6 |
| Claude Haiku 4.5 | ~₹1.5 | ~₹450 |
| Claude Opus 5, whole corpus in every prompt (rejected) | ~₹12 | ~₹3,600 |

Hugging Face prices are the hosts' own, passed through without markup, as
listed at `https://router.huggingface.co/v1/models` on 16 September 2026.

**Prompt caching is not used.** On Claude Haiku 4.5 it cannot be — Haiku
caches only prefixes of 4,096 tokens or more, and Arka's whole prompt is well
under that. On the open models the prompt is too cheap for it to matter.

## Budgets

- First sentence visible within 3 seconds at p95.
- Under ₹0.05 a turn on the default model. Every turn logs its model, prompt
  version, tokens and estimated cost (`chat.turn`).
- **A hard spending limit must be set with the model provider before
  launch** — Hugging Face billing, or the Anthropic workspace if switched
  back. The provider enforces it; the site cannot. The in-app rate limit
  is per server instance and is best-effort only (`rate-limit.ts`).

## Data leaving the site

| What | To | Notes |
|---|---|---|
| Visitor questions, with phone numbers, emails and links removed first | Hugging Face, which forwards them to the pinned host (Novita); or Anthropic if switched | Retention per the provider's API data policy and the organisation's settings |
| Lead details and the conversation | Resend, then the sales inbox | Sent only after the visitor ticks consent |

Nothing is stored on the site. Logs carry ids, counts and outcomes — never a
name, number, email or message (`log.ts` accepts no free-text field).

## Choosing an open-source model

Hugging Face Inference Providers is the simplest route: one token, open
models from several hosts at the hosts' own prices with no markup, and the
same OpenAI-compatible interface the adapter already speaks
(`https://router.huggingface.co/v1`). Pin the provider in the model id
(`…:groq`) so the model that passed the eval is the one visitors get; the
unpinned default routes each request to whichever host is fastest.

**The default was chosen before the eval could be run** — no token existed
on the machine that built this. Run `npm run eval:arka` before launch and
treat every refusal case as a must-pass: a miss on an answer case is a
judgement call, a miss on a refusal case is not. If the 70B misses one, fix
the persona or move to Claude Haiku 4.5. A full run costs well under ₹1 on
the default.

## Consequences

- **The privacy policy at `/privacy` is interim**, written from what the site
  does, until the client's approved text arrives. Its list of AI providers is
  read from Arka's configuration, so it follows a model switch. The consent
  line in the form links to it.
- **The eval is not in CI.** The repository has no CI, and adding it is a
  pipeline decision — as is spending ~₹5 a run on every merge. Until then it
  is run by hand before any change to the persona, the corpus or the model.
- **When a content warning is resolved, delete its `WITHHELD` entry** and the
  fact flows back into Arka's answers.
- **Rate limiting is per instance.** If abuse appears, replace `rate-limit.ts`
  with Upstash Redis; its signature is the seam.
- **Changing the persona means bumping `PROMPT_VERSION`**, so a shift in
  answers can be traced in the logs to the prompt that produced it.
